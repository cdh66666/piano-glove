# 六自由度钢琴手套 · Piano Glove

用 6 个舵机驱动的可穿戴手套：通过连杆/绳驱带动佩戴者的手指按压琴键。
**上层玩法是导入 MIDI 文件，让手套按原曲的节奏和速度带动你的手指** —— 戴上去感受大师级的演奏。

## 当前交付 · 2026-10-01 · STS3032-C001

- [公网指法预览](https://cdh66666.github.io/piano-glove/)：三段右手原谱和指法动画，不访问串口、不控制远端设备。
- [下载完整调试台与固件源码](https://github.com/cdh66666/piano-glove/archive/refs/heads/main.zip)：解压，安装 Python 3（加入 PATH），双击 `host/start-debug.bat`。首次自动安装 pyserial；本机调试台提供编号、校准、动作、测速和曲目演奏。
- 贵舵机固件源码在 `firmware/`，主控为微雪 Servo Driver with ESP32（SKU 21593），构建环境由 `firmware/platformio.ini` 固定。详见 [STS 适配记录](docs/STS3032-ADAPTATION.md)。
- ID1 为拇指外展/内收，ID2 为拇指按压，ID3–6 为食指至小指。曲目中 ID1 保持抬起位置，五根按压轴在抬起和按下端点间运动，不逐音回中点。
- STS 控制使用校准行程中央 90%，默认速度命令 8000 counts/s。更换手套或舵机后重新编号、校准；本机校准记录不上传。
- 本轮三段曲目实机完成，含准备收尾分别约 5.23 / 3.92 / 3.92 秒；谱内演示为 120 / 80 / 80 BPM。这是演示拍速，不是原谱标定速度。相关软件回归 152 项通过；数字检查不替代每副手套的实测。

公网站点由 `.github/workflows/pages.yml` 部署，`site/` 为独立静态预览；`scripts/build-public-site.cjs` 从本机调试台同一份曲目数据生成并复制原谱图片。公开站点不代理本机 API。

### 旧版说明与历史测试记录
> **历史状态（2026-09-26，非本次 STS 适配验收）**
> - **固件 `PIANO_GLOVE_2` v2.2.3**：稳态吞吐 ≈ **1421 条/秒**（原厂 9.9 条/秒）；
>   **6 块舵机全部在线**，实机逐根验证 `MOVE` 真的产生位移（271~592 计数，`servo_err` 不涨）
> - **演奏是闭环的**：演奏中 ~25Hz 用 `POSALL` 一帧读回每根手指的**真实位置**，
>   发一个音之前先确认这根手指上一次的动作真的做完了 —— 没做完就**丢掉这个音**
>   （**丢音保节奏**：与其抢拍糊成一片，不如少一个音）。不是"照谱猛发、不管有没有按下去"
> - **两套舵机都能认**（`STS3032` / `SC09`）：开机读舵机自己的寄存器判家族与量程、存 NVS，
>   `PROFILE AUTO` 可随时重探。⚠️ 官方明确**不同系列不能挂同一条总线** → 换整套，不是混插
> - **按压深度 = MIDI 力度**（弱音 20% ~ 强音 100%，5:1 动态）；
>   **「手指行程时间」不再让人手填** —— 点一下由板上自测（`RATE` 本身就是闭环）
> - **校准记的是轨迹，不是极值**（v2.2.3）：128 桶直方图 + 环形挑主簇 ——
>   一次离群读数再也撑不开量程（详见 [firmware/README.md](firmware/README.md)）
> - **速度已实测达标**：满行程 **4.97 Hz**（保底 4 Hz ✓），行程压到 60% → **7.18 Hz**（6 Hz ✓）
> - **音乐 ↔ 演奏动作同轴显示**：演奏时浏览器现场合成声音；卷帘图上半张画曲子（音高 × 时间）、
>   下半张逐根画参与演奏的手指的动作，共用一根播放头 —— **听到的 = 看到的 = 手套做的**
> - **演奏速度分级**：曲库每首自带本级建议速度（L1 90% → L5 200%，选中即套用），滑块上限 250%；
>   旁边实时算出「当前速度相当于手套上限的几倍」—— **极限在哪是看得见的数字**。
>   L5 故意超上限，用来压测固件的丢音降级
> - **声音「提前提交」，不是让动作晚**：物理出声 = 提交 + 60ms 固定延迟（声卡自报），
>   声音由**独立游标**推进；**起音点** = 手指走完**行程的一半**就响（跟真钢琴一样压到中段击弦）
> - **演奏一结束全部舵机失能**（「奏完失能」默认开，可关），底下是**先回位、后断电**的固定顺序
> - **声音可自证**：演奏页有「🔔 试听一下」和一行常驻音频状态 ——
>   再遇到"没声音"时，`host/tests/diag_sound.js` 会逐环量出来**到底断在哪一级**
> - **串口不走浏览器**：`host/bridge.py` 在本机进程里用 pyserial 开串口，页面只发 HTTP。
>   于是**侧边栏浏览器 / 内嵌 WebView 也能连板子**（它们没有 `navigator.serial`，原来必然连不上）。
>   串口**自动选、自动连**：按芯片型号打分 → 逐个问 `INFO` → 谁答连谁，拔了再插自己回来；
>   界面上没有"选模式"这一步，也没有模拟模式
> - 调试台分页式；**页面端到端自测 219 项 + 串口桥自测 43 项全绿**（脚本自报总数），
>   演奏那条路的变异测试 **20 处**（逐条往代码里注入退化，确认对应的断言真的会红），
>   MIDI 解析器经独立实现交叉验证
> - **实机复验通过（用户实测）**：试动作满幅度、不再撞限位；完整曲目演奏节奏正确
> - 演奏样本自带**《两只老虎》**，另有 **10 首分级曲库**（L1 入门 → L5 挑战）可在演奏页下拉直选；
>   样本**不含指法**，手指分配由程序现场算，指法表见 [`host/samples/FINGERING.md`](host/samples/FINGERING.md)

## 硬件

| 项目 | 规格 |
| --- | --- |
| 主控板 | 微雪 **Servo Driver with ESP32**（SKU 21593）：ESP32 + CP2102 + OLED + WiFi + DC 6~12V 供电 |
| 主控固件 | **自研 `PIANO_GLOVE_2`**（本仓库 `firmware/`，源码在手）。原厂闭源 `PIANO_GLOVE_1` 已备份，无串口透传 |
| 舵机 | 6 × **Feetech STS3032-C001**：12bit 磁编码，量程 0~4095（360°），工作电压 4.8~6V，TTL 半双工 |
| 另一套舵机 | 6 × **Feetech SC09**（SCSCL 族）：10bit，量程 0~1023（300°），**无速度反馈**，仅位置 + PWM。固件同样支持（`PROFILE AUTO` 自动认），但**不同系列不能挂同一条总线** —— 换就换整套。详见 [hardware/README.md](hardware/README.md) |
| PC ↔ 板 | USB-C（UART0），**固定 115200 8N1** |
| 板 ↔ 舵机 | UART1，**GPIO18=RX / GPIO19=TX，1,000,000 bps** |
| 供电 | **5V/5A 适配器接 DC 圆口**（USB-C 只给板子供电，不带舵机） |
| 舵机数 / 自由度 | 6 个舵机，但**能独立按琴键的只有 5 根**：拇指 2 个舵机是「1 根按压 + 1 根侧摆摆位」，其余四指各 1 |

> ⚠️ 方向别搞混：这只手套是**被 MIDI 驱动去动手指**的，不是把手指动作转成 MIDI 的输入型设备。

### 槽位 ↔ 舵机（固件默认）

| slot | 名称 | 角色 | 参与演奏 | 默认舵机 ID |
| --- | --- | --- | --- | --- |
| 0 | 拇指按压 | 把拇指压到琴键上 | ✔ | 1 |
| 1 | 拇指侧摆 | 演奏前把拇指摆到能压到键的位置（使能位） | ✘ | 2 |
| 2 | 食指 | 按压 | ✔ | 3 |
| 3 | 中指 | 按压 | ✔ | 4 |
| 4 | 无名指 | 按压 | ✔ | 5 |
| 5 | 小指 | 按压 | ✔ | 6 |

> ⚠️ **ID 映射已实机核对**（槽位 0~5 → 舵机 1~6，`[1,2,3,4,5,6]`）。
> **拇指两轴的命名改过**（2026-09-20）：实机确认出厂标签是反的 ——
> 真的"按下去"是 slot0，真的"往旁边摆"是 slot1。
> 哪根是哪根在调试台第 4 步能一键对调（只换角色，不动 ID、不作废校准）。
> 如果某根长指的按压感觉反了，用 `SETDIR` 单独修正即可，**不用重做编号**。
> 详见 `docs/design-notes.md` §3.5。

## 七个最容易踩的坑

1. **PC 侧别直接发原始 Feetech SCS 包。** 板子对外是**文本命令协议**，没有串口透传；舵机原始包发过去毫无反应。
   文本命令表见 [docs/handoff-2026-09-17.md](docs/handoff-2026-09-17.md#2-固件-piano_glove_1-命令协议核心)。
2. **6 个舵机出厂 ID 全是 1，不是 1~6。** 同时挂上总线会互相抢答。**改号必须一次只接一个舵机**；
   而且编号向导第 N 轮插上来的新舵机**也是 1** —— 所以「改号」和「给这个槽位登记 id」是两件事，
   混为一谈会把上一轮编好的槽位一起改掉。详见 [docs/design-notes.md](docs/design-notes.md) 风险 3。
3. **校准是按「槽位」存的，不是按舵机 ID 存的。** 一旦动过 `MAP` / `SETID`，旧校准立即作废，
   **必须重做第 3 步校准**。拿错校准去按压可能直接顶到机械限位。
   （例外：若偏差只是**静止位取错端点**造成的，`snapStandby()` / `CAL ALIGN` 会自动修好，
   不用重做采样 —— 2026-09-18 的 6 个槽位就属于这种，现已全部达标。）
   `host/tests/bench_move.py` 内置了这道安全闸（校准确与当前位置差超过 600 计数就拒绝动作）。
   想先体检不重做，用 `host/tests/diag_cal.py` 把 6 槽的 `min/standby/max/方向/当前位置` 全列出来。
4. **改完固件一定要真烧录并回读 `INFO ver=` 复核。** 「本地编译通过」不等于「板子上跑的是这版」——
   曾经因此出现过「试动作点了只锁电机不动」：板子上还是旧版本，新代码从没烧进去。
5. **`standby`（静止位）必须落在「松开端」，不是量程中点。** 取中点的话
   `pressPos(s,100)` 只从**中点**走到按下端，按压幅度只剩你校准行程的**一半** ——
   表现就是「怎么幅度这么小」。v2.1.2 已修，并对存量校准加了开机自动对齐（`snapStandby()` / `CAL ALIGN`）。
6. **`MOVE <id> <pos>` 收的是原始寄存器位置，不要在界面上硬编码。** 曾经写死 `MOVE 1 200`，
   而 `200` 对 6 块舵机**全部**落在校准区间外，舵机一路顶到限位卡死。
   现在固件有越界闸（要越界得显式带 `FORCE`），界面则改用 `PRESS`/`RELEASE` 走校准区间。
7. **校准表里「幅度 100%」不代表好事 —— 那很可能是被污染了。** 采样如果只记最低/最高，
   一次离群读数（或一次没读到）就能把行程撑成满量程；症状是**演奏时这根手指会走满整圈、拧连杆**，
   而表里它偏偏显示成最好看的 100%。v2.2.3 已改成从**轨迹**里挑主簇，校准表也会把
   跨度 >90% 的槽位**标红**。详见 [firmware/README.md](firmware/README.md) 的 v2.2.3 那节。

## 快速开始

### 网页调试台

**Windows 一键启动**：双击 `host/start-debug.bat`

它会起一个**本地串口桥**（`host/bridge.py`，127.0.0.1:8123）并打开调试台。串口由这个 Python 进程用 pyserial 直接打开，**页面只发 HTTP**。

> **为什么要这样绕一下**：网页想开串口只有 Web Serial（`navigator.serial`）这一条路，而它
> - 只有电脑版 Chrome / Edge 有；
> - 要求安全上下文，`file://` 打开直接没有；
> - **侧边栏浏览器、内嵌 WebView、微信/豆包内置浏览器一律没有**。
>
> 结果就是「在侧边栏里点连接永远没反应」—— 那不是驱动问题，是那个浏览器没有这个 API。
> 把串口挪到 Python 侧之后，**任何能打开网页的浏览器都能连板子**。

手动方式：

```bash
cd host
python bridge.py                 # 起桥（默认 127.0.0.1:8123，自动扫描 + 自动连接）
python bridge.py --port 8123 --url COM4    # 想写死某个口也行
```

然后浏览器打开 <http://127.0.0.1:8123/web_piano_glove.html>。

**不用选串口、不用点连接**：桥会枚举本机串口 → 按芯片型号打分 → 从高到低逐个打开、问一句 `INFO` → 谁回 `OK INFO` 就连谁。板子拔了再插会自己连回来。界面上没有「模拟模式」这种选项，只有一条真串口的路。

> 打分规则：CP210x（微雪板载，100）> CH340（92）> ESP32-S3 原生 USB（88）> FTDI（84）> 认不出芯片的 USB 口（20）。
> 蓝牙虚拟口、主板自带 ACPI 通信口、并口直接拉黑，不去浪费那一次开关串口（**开串口会让 ESP32 复位**，多开一次就多等一轮启动）。
>
> 波特率固定 **115200**。
