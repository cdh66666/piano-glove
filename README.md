# 六自由度钢琴手套 · Piano Glove

用 6 个舵机驱动的可穿戴手套：通过连杆/绳驱带动佩戴者的手指按压琴键。
**上层玩法是导入 MIDI 文件，让手套按原曲的节奏和速度带动你的手指** —— 戴上去感受大师级的演奏。

> **状态（2026-09-18 晚）**
> - **固件自研完成**（`PIANO_GLOVE_2` v2.1.2）：稳态吞吐 ≈ **1421 条/秒**，比原厂快两个数量级
> - **6 块舵机（`id=1..6`）全部在线**，实机逐根验证 `MOVE` 真的产生位移（271~592 计数，`servo_err` 不涨）
> - **按压幅度 = 完整校准行程**：修掉「静止位取量程中点 → 只按半个行程」，实机 6 槽全部达标
> - **消除撞限位**：`MOVE` 加校准区间越界闸；界面不再硬编码 `MOVE 1 200`（它本来对 6 槽全部越界）
> - **速度已实测达标**：满行程 **4.97 Hz**（保底 4 Hz ✓），行程压到 60% → **7.18 Hz**（6 Hz ✓）
> - **音乐 ↔ 演奏动作同轴显示**：演奏时浏览器现场合成声音；卷帘图上半张画曲子（音高 × 时间）、
>   下半张画 6 根手指的动作，共用一根播放头 —— **听到的 = 看到的 = 手套做的**
> - 调试台分页式、含模拟固件；**模拟端到端自测 121 项全绿**（脚本自报总数，新增断言均做过变异测试），MIDI 解析器经独立实现交叉验证
> - **实机复验通过（2026-09-18 用户实测）**：试动作满幅度、不再撞限位；完整曲目演奏节奏正确
> - 演奏样本自带**《两只老虎》**，另有 **10 首分级曲库**（L1 入门 → L5 挑战）可在演奏页下拉直选；
>   样本**不含指法**，手指分配由程序现场算，指法表见 [`host/samples/FINGERING.md`](host/samples/FINGERING.md)

## 硬件

| 项目 | 规格 |
| --- | --- |
| 主控板 | 微雪 **Servo Driver with ESP32**（SKU 21593）：ESP32 + CP2102 + OLED + WiFi + DC 6~12V 供电 |
| 主控固件 | **自研 `PIANO_GLOVE_2`**（本仓库 `firmware/`，源码在手）。原厂闭源 `PIANO_GLOVE_1` 已备份，无串口透传 |
| 舵机 | 6 × **Feetech STS3032-C001**：12bit 磁编码，量程 0~4095（360°），工作电压 4.8~6V，TTL 半双工 |
| PC ↔ 板 | USB-C（UART0），**固定 115200 8N1** |
| 板 ↔ 舵机 | UART1，**GPIO18=RX / GPIO19=TX，1,000,000 bps** |
| 供电 | **5V/5A 适配器接 DC 圆口**（USB-C 只给板子供电，不带舵机） |
| 自由度 | 6：拇指 2 个（下压 + 侧压），其余四指各 1 个 |

> ⚠️ 方向别搞混：这只手套是**被 MIDI 驱动去动手指**的，不是把手指动作转成 MIDI 的输入型设备。

### 槽位 ↔ 舵机（固件默认）

| slot | 手指 | 默认舵机 ID |
| --- | --- | --- |
| 0 | 拇指侧压 | 1 |
| 1 | 拇指下压 | 2 |
| 2 | 食指 | 3 |
| 3 | 中指 | 4 |
| 4 | 无名指 | 5 |
| 5 | 小指 | 6 |

> ⚠️ **ID 映射已实机核对**（槽位 0~5 → 舵机 1~6，`[1,2,3,4,5,6]`）。
> 角色体感已由用户实机试戴过（2026-09-18）；若某根手指的「侧压 / 下压」感觉反了，
> 用 `SETDIR` 单独修正即可，**不用重做编号**。

## 六个最容易踩的坑

1. **PC 侧别直接发原始 Feetech SCS 包。** 板子对外是**文本命令协议**，没有串口透传；舵机原始包发过去毫无反应。
   文本命令表见 [docs/handoff-2026-09-17.md](docs/handoff-2026-09-17.md#2-固件-piano_glove_1-命令协议核心)。
2. **6 个舵机出厂 ID 全是 1，不是 1~6。** 同时挂上总线会互相抢答。**改号必须一次只接一个舵机**；
   而且编号向导第 N 轮插上来的新舵机**也是 1** —— 所以「改号」和「给这个槽位登记 id」是两件事，
   混为一谈会把上一轮编好的槽位一起改掉。详见 [docs/design-notes.md](docs/design-notes.md) 风险 3。
3. **校准是按「槽位」存的，不是按舵机 ID 存的。** 一旦动过 `MAP` / `SETID`，旧校准立即作废，
   **必须重做第 3 步校准**。拿错校准去按压可能直接顶到机械限位。
   （例外：若偏差只是**静止位取错端点**造成的，`snapStandby()` / `CAL ALIGN` 会自动修好，
   不用重做采样 —— 2026-09-18 的 6 个槽位就属于这种，现已全部达标。）
   `host/tests/bench_move.py` 内置了这道安全闸（校准确与当前位置差超过 600 计数就拒绝动作）。
   想先体检不重做，用 `host/tests/diag_cal.py` 把 6 槽的 `min/standby/max/方向/当前位置` 全列出来。
4. **改完固件一定要真烧录并回读 `INFO ver=` 复核。** 「本地编译通过」不等于「板子上跑的是这版」——
   曾经因此出现过「试动作点了只锁电机不动」：板子上还是旧版本，新代码从没烧进去。
5. **`standby`（静止位）必须落在「松开端」，不是量程中点。** 取中点的话
   `pressPos(s,100)` 只从**中点**走到按下端，按压幅度只剩你校准行程的**一半** ——
   表现就是「怎么幅度这么小」。v2.1.2 已修，并对存量校准加了开机自动对齐（`snapStandby()` / `CAL ALIGN`）。
6. **`MOVE <id> <pos>` 收的是原始寄存器位置，不要在界面上硬编码。** 曾经写死 `MOVE 1 200`，
   而 `200` 对 6 块舵机**全部**落在校准区间外，舵机一路顶到限位卡死。
   现在固件有越界闸（要越界得显式带 `FORCE`），界面则改用 `PRESS`/`RELEASE` 走校准区间。

## 快速开始

### 网页调试台（推荐，无硬件也能玩）

**Windows 一键启动**：双击 `host/start-debug.bat`
—— 它会（必要时）起好 127.0.0.1:8123 的静态服务，再用 Chrome/Edge 打开调试台。

手动方式：

```bash
cd host
python -m http.server 8123 --bind 127.0.0.1
# 浏览器打开 http://localhost:8123/web_piano_glove.html
```

选「模拟模式」点连接，就能把 **编号 → 校准 → 试动作 → MIDI 演奏** 整条链路走完，不接硬件即可验证。

> ⚠️ **连实机必须用 Chrome 或 Edge，且必须走 `http://localhost`，不要双击 html 走 `file://`。**
> 串口能力来自 Web Serial（`navigator.serial`）：
> - `file://` 下拿不到串口权限；
> - 部分国产浏览器的内置内核不暴露 `navigator.serial`（界面上「连接」永远扫不到板子）。
>
> 波特率固定 **115200**。

### 无硬件自测

```bash
cd host/tests
python make_midi.py && python ref_parse.py && node compare.js   # MIDI 解析器交叉验证
node e2e.js                                                     # 端到端流程，121 项检查
```

### 实机验证（插上板子和舵机）

```bash
cd host/tests
python bench_move.py              # 验「舵机真的动了」：发指令前后各读一次位置，比差值
python bench_move.py --slot 1,2,3 # 只测某几根
python diag_state.py              # 读板子落在 NVS 里的真实状态（编号 / 校准 / 总线诊断）
```

详见 [host/tests/README.md](host/tests/README.md)。

### Python 命令行

```bash
cd host
pip install -r requirements.txt

python glove_fw.py info                    # 固件 / 档位 / 校准 / armed 状态
python glove_fw.py assign                  # 逐个把舵机 ID 编成 1~6
python glove_fw.py auto                    # 固件自检（含诊断建议字段）
python glove_fw.py status                  # 6 槽位总表
python glove_fw.py cal wizard 20           # 一键校准向导（20 秒活动时间）
python glove_fw.py monitor                 # 轮询实时反馈
python glove_fw.py raw "CAL STATUS"        # 发任意命令
```

板子串口**自动识别**：`glove_fw.py` 会挨个串口发 `INFO`，回 `OK INFO` 的那个就是手套。串口号随 USB 枚举变化，别写死；要指定就 `--port COMx`。

| 配置 | 实测 |
| --- | --- |
| 单根，满行程 | **7.10 ~ 7.15 Hz** |

| 5 根同步，行程 40% | 9.30 Hz |

是牺牲行程保频率，还是牺牲频率保行程？倾向保频率 —— 见 [docs/design-notes.md](docs/design-notes.md) §2 Q9。
