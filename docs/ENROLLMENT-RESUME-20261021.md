# 钢琴手套编号中断续编修复 · 2026-10-21

固件保留协议版本 2.2.4 / enroll_flow=3，新增 `enroll_resume=1 enroll_fix=20261021`。网页新增“继续编号（保留进度）”；“重新编号”仍表示从空总线重新排布物理顺序。

![保持六台接线完成续编的流程](images/enrollment-resume-20261021.svg)

## 现场故障

本地保留了 1934 行原始操作日志，未随公共仓库上传。第六台 ID1→15 实际写入成功，但 5ms 单次查询失败后立即进入 FAILED；后续 17 次完整扫描均找到 15～20。编号没有进入正式 1～6 转换。此前还出现型号读取失败、临时地址漏回应和最后 USB 消失，不能单凭这些日志认定供电或线束的物理根因。

## 修复

- 改号只写一次，随后重复查询旧址缺席和新址响应；连续两次有效读回才确认。持续失败保持可诊断状态，允许显式续编，不重复盲写 EEPROM。
- `ENROLL RESUME` 先读取已有 NVS 临时槽位映射，作为恢复下限；两次完整扫描后按临时地址 20～15 重建槽位顺序。正式编号转换到一半的“正式前缀＋临时后缀”也可继续。
- 恢复先核对所有响应者型号、关闭扭矩、读回扭矩和 EEPROM 锁，再补齐映射。已确认设备漏回应时不降低进度，不复用其地址。
- 新接入的单台仍须经过正常两次扫描。无法确定顺序、多余地址、型号混杂等不进入最终转换，不要求把六台拔下来重排。
- 页面只在用户点击“继续编号”时发送 RESUME；USB 重连不会自动发该命令。保留原有校准与动作入口。
