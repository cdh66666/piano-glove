## 能使用的部分

`host/score_converter.py` 为本地电脑版转换入口：PDF → 带原谱位置的复核草稿 → 已核对的右手 `.pgl`。没有串口/硬件调用，导入和导出不会启动手套。`score_converter_engine.py` 来自本项目早期 `piano-score-trainer/recognizer.py` 的通用矢量识谱规则，本次修正两类真实错误，不通过文件名查询曲目答案。

Python接口：

```python
from score_converter import recognize_pdf, export_reviewed
from score_codec import encode
project = recognize_pdf(pdf_path, bpm=120)
# 对照PDF核对/补录右手、pitch、finger、beat、duration_beats。
# 每音confirmed=True，所选区间selection.range_reviewed=True后导出。
pgl = encode(export_reviewed(project))
```

命令：`python host/score_converter.py 原谱.pdf 草稿.review.json --bpm 120`；核对后：`python host/score_converter.py 草稿.review.json 曲目.pgl`。

依赖 `pypdfium2==5.13.0`；生产识谱已移除 PyMuPDF/`fitz`。这里的拍是四分音符为一拍。音高转换为MIDI音符，保留和弦、长音、休止和尾部休止；不以机械动作时长代替乐谱音符时值。

延音线需要对照原图处理：把第一个音的时值改为相连音符的总时值，并排除续接音，输出一个持续音；不同音高之间的连音线不这样合并。页面的“时值”和“排除”支持这条复核路径，未经核对不会自动合并。

导出只接受已确认的右手1至5指音符。未知左右手、缺失音高/起拍/时值/指法、同一手指重叠均阻止导出；明确排除的候选不执行。只有原谱有指法才提取指法，不用音高编造指法。

## 查到并修正的问题

1. **连音/指法警告错误阻断独立可靠节拍。** 原规则要求音符无任何issue才能填全局拍，因连音线或和弦指法仍需核对，已经通过整小节拍数验证的起拍也被清空。本次仅由节拍相关问题阻断起拍；保留连音/指法警告和人工确认，不自动处理延音线。
2. **右手低音误借左手指法。** 《南瓜布吉舞》右手第3小节第二个C4，原规则按竖直距离借到两谱表之间的左手“2”，原图实际右手“1”在符头上方。本次优先匹配完整的右手上方指法组，得到1。若原谱在符头下方标指法，则保留候选并额外标记需要人工复核；不自动编指法。真实《雨终曲》的下方指法3/5仍保留并通过回归核对。
3. **最终休止丢失。** 导出原先只取最后音结束作为曲目时长；现在保留选择的结束拍，阿拉伯风的尾部八分休止被保留。

## 2026-10-11导出与后端修正

- 导出支持识谱器已产生的重升音名（如F##5），同时接受核对输入的重降音名；转换成正确MIDI半音值。
- 跨页的页/谱表组/小节范围按原谱顺序比较，页与谱表组编号重新起算时不会被错误排除；源位置缺失和反向区间明确报错。
- PDFium保留字形Unicode、位置、矩阵缩放字号及矢量路径。`pdf_backend.PDF_LOCK` 在一个进程内串行保护识谱和预览；没有硬件调用。[PDFium原始文本接口](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdf_text.h)、[路径接口](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdf_edit.h)、[线程限制](https://pypdfium2.readthedocs.io/en/stable/python_api.html#incompatibility-with-threading)。
- 新旧后端仅5个时值字段不同，已渲染原谱核对：月光奏鸣曲第3页两音旧版把相邻左手横梁算入，误报0.25拍，新版为原图的0.5拍；一条大河第5页三个高音旧版没有解出符干，新版为原图的0.5拍。这5音仍未自动确认，保留原谱复核流程。不是完整曲目的准确率证明。

目前不支持旋转页或非零裁切起点的矢量识谱，明确报错，不返回被错位识别的音符；此次30份原PDF不触发该条件。扫描页仍可显示原图并手动补录，补录确认后走同一导出校验。
