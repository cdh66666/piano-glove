## 结束状态与未测项

设备保持USB连接、停止、普通模式，六轴扭矩关闭；重连不恢复运动目标。本轮曾验证Codex侧栏visible=true且真实页面已加载，标签已保留、幅度20%。收尾时visible=false，重新打开返回queued；当前不能宣称侧栏仍显示，回到本聊天时将处理打开请求。

空载轴在曲谱末尾卸力后出现惯性漂移，用户已确认无任何结构连接。该现象保留在日志中，未据此重写校准或改动结束策略。

曲库第77条读取时Windows报告 `ClearCommError / 拒绝访问`，COM3重新出现且USB位置由1-9变为1-8.1.3。重连启动日志出现POWERON_RESET；同一主控热点标识与校准epoch一致，六轴扭矩读回0，未恢复动作。仅续读77—100，先前76条不重复。该次中断的原因未定，不能称USB全程无中断，也不能据此认定舵机总电源确实完全切断。

**待修界面问题**：串口恢复且设备反馈新鲜后，侧栏仍出现“未连接 · STS3032-C001 · 已就绪”和“曲库尚未就绪”。`host/software.js:109`初始化只读取一次连接标识/曲库，定期设备状态刷新没有完整重做初始化。刷新页面已恢复“USB COM3 · STS · 已就绪 / 待机”；这是已验证的临时恢复方法，不是永久修复。本轮测试报告保留该发现，控制/页面源码未改。

该发现后续已处理：`reconnect-20261015a` 自动恢复连接身份、能力与曲库，119项受影响界面回归通过，空载实机重连无需刷新且不恢复动作。完整证据与仍未解决的底层USB中断原因见[同日后续修复报告](SOFTWARE-RECONNECT-FIX-20261015.md)。
