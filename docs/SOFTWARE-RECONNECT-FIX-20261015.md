> 后续更新：同日教程简化版 `beginner-guide-20261015b` 已完成实现/视觉/自动测试并写入主控，重连实现保持不变；最新固件身份及教程证据见[教程简化报告](SOFTWARE-BEGINNER-GUIDE-20261015.md)。本报告保留重连修复阶段的版本与实测记录。

界面重连后连接标识、曲库和控件不自动恢复的问题已修复，并在当前 COM3 主控与六轴空载电机上验证。页面无需重新加载即可恢复设备身份、100 条曲库及可用控件；连接恢复不会重新开始此前的训练或播放。

本轮测试背景仍为用户明确确认的裸输出轴：结构全部拆下，六个舵机输出轴未连接任何东西。结果只覆盖电脑网页、通信和空载动作，不代表装配、负载或穿戴验收。

## 版本与修复范围

- 本轮已验证界面版本：`reconnect-20261015a`。
- 写入设备的应用分区：地址 `0x10000`，大小 **1,048,400 字节**，SHA256 `8fc95d5019f381e51aa596bd1e2baae425c0c1e93e7ffd0e423bc652c3423c4f`。
- 固件由冻结来源构建；相对已验证 r9，仅 `host/software.html` 和 `host/software.js` 变更，7 个界面资源与此次编译内容一致。运动控制源码未变。
- 写入前保留 NVS 备份，写入后独立 Flash 校验通过；校准参数、100 条曲库索引保持一致。本轮没有重写校准或重新上传全部曲库。
- 当前两个打开的软件标签已加载本修复版本。随后用户新增“第 3 课及后续读谱教程看不懂”的请求，教程简化正在进行；本报告不证明后续教程改动已经验收或同步到设备。
- **旧 r9 ZIP 未重新打包**，不能将已有安装包视作包含本次修复。

原问题是启动时只读取一次设备身份，恢复状态轮询时没有完整重读连接信息；曲库曾就绪时也可能继续沿用旧标识。现在恢复流程依次读取身份与能力、曲库和新的位置反馈，全部成功后才开放控件。失败按 2 秒间隔重试，同一时刻只保留一条恢复流程；新的断开会使旧的异步结果失效。

最终状态确认与常规轮询协调执行，避免串口响应较慢时被下一次轮询作废。恢复期间新建曲库按钮、播放页“重新开始”继续禁用，播放入口本身也检查可用状态。PDF 校对数据、播放器原谱和停止后的进度保留；连接恢复只恢复界面，不补发动作。

上述“无需重新加载页面”的 UI 结论来自主代理在本次会话中的实时 CUA 检查；设备状态及扭矩结论由已保存 JSON 和读回日志支持。文档收尾只核对既有证据与进度 API，没有再次驱动硬件。这里的断开/重连指主控串口连接断开与重建，不等同于人工拔插 USB 或舵机总电源断电试验。
