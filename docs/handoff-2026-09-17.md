## 0. 先看这里：最容易踩的三个坑

1. **板子上的固件不是微雪出厂固件，而是自定义的 `PIANO_GLOVE_1` 固件**，它**没有串口透传功能**——所以直接发 Feetech SCS 原始舵机包是**没有任何反应**的（这是项目前期最大的弯路）。必须用文本命令协议（见 §2）。
2. **6 个舵机出厂 ID 全都是 1**（不是 1~6）。多个同 ID 舵机挂在同一条总线上会互相抢答，表现为「偶尔 ping 通、读位置失败、SCAN 只找到 1 号」。**必须一次只接一个舵机改号**。
3. **固件 `PING` 单次固定耗时约 610ms**（固件内部固定等待窗口，不是硬件慢）；`SCAN` 又有约 1/3 概率漏报（返回 `count=0`）。所以**探测舵机请用逐个 `PING`，不要依赖 `SCAN`**。

## 1. 硬件

| 项目 | 规格 / 说明 |
|---|---|
| 主控板 | 微雪 **Servo Driver with ESP32**（SKU 21593）：ESP32 主控 + **CP2102** USB 转串口 + OLED + WiFi + DC 6~12V 供电口 |
| 板子串口 | PC ↔ 板子：USB-C（UART0）**固定 115200**；板子 ↔ 舵机总线：UART1，**GPIO18=RX / GPIO19=TX，1,000,000 bps** |
| 舵机 | 6 × **Feetech STS3032-C001**：ST 系列、12bit 磁编码、量程 **0~4095**（360°）、工作电压 **4.8~6V**、出厂 ID 全为 1、协议 TTL 半双工 |
| 供电 | **5V/5A 适配器接 DC 圆口**给舵机供电（USB-C 只给板子）。实测舵机反馈 `voltage_raw=57` → **5.7V，正常** |
| 舵机总线接线 | 全部并联/串联在同一总线上，3 线（GND / Vcc / Signal） |
| 手套结构 | 6 自由度：**拇指 2 个舵机（一个下压、一个侧压）**，其余四指各 1 个 |

|---|---|---|
| 0 | 拇指侧向（侧压） | 1 |
| 1 | 拇指按键（下压） | 2 |
| 2 | 食指 | 3 |
| 3 | 中指 | 4 |
| 4 | 无名指 | 5 |
| 5 | 小指 | 6 |

> ⚠️ **待核实**：用户口头描述曾是「id1=下压、id2=侧压」，与固件默认相反。上手后请用 `MOVE <id> <pos>` 逐个驱动并观察哪根手指动、往哪个方向动，必要时用 `MAP <slot> <id>` 重映射、`SETDIR <slot> max|min>` 修正按压方向。

## 2. 固件 `PIANO_GLOVE_1` 命令协议（核心）

- 波特率 **115200 8N1**，命令为 **ASCII 文本，以 `\r\n` 结尾**；回复按行返回，行首为 `OK ...` 或 `ERR ...`
- 固件启动横幅（复位时 UART0 输出，可用于确认板子在跑什么固件）：
  ```
  READY FW=PIANO_GLOVE_1 boot_motion=0 torque=off
  READY PROFILE=SC09 range=1
  ```
- 板子自带 WiFi AP **`PIANO_GLOVE_A50528`**，网页界面在 **http://192.168.4.1**（功能未探索，可作备选调试入口）
- 命令表（`HELP` 返回）：
  `INFO PROFILE AUTO ENROLL SCAN PING STATUS STATUS_ALL MAP SETDIR SETID CAL TORQUE ARM DISARM SAFE STANDBY PRESS RELEASE MOVE DEMO`

### 2.1 已实测确认的命令与回复

| 命令 | 回复示例 | 说明 |
|---|---|---|
| `INFO` | `OK INFO fw=PIANO_GLOVE_1 profile=STS3032 range=4095 ap=PIANO_GLOVE_A50528 ip=192.168.4.1 calibrated=0 armed=0 auto_active=0 enroll_active=0 enroll_next=1 enroll_temp=10 enroll_phase=OFF` | 全局状态 |
| `PROFILE SC09` / `PROFILE STS3032` | `OK PROFILE name=STS3032 range=4095` / `ERR PROFILE must_be_SC09_or_STS3032` | **STS3032 舵机必须选 STS3032**（SC09 下 ping 不通） |
| `PING <id>` | `OK PING id=1` / `ERR PING id=2` | 单次约 610ms |
| `SCAN` | `SCAN_BEGIN profile=STS3032 max=20` / `FOUND id=1` / `SCAN_END count=1` | ⚠️ 约 1/3 概率漏报，勿依赖 |
| `STATUS <id>` | `OK STATUS id=1 profile=STS3032 pos=447 speed=0 load=0 voltage_raw=57 temperature=35 current=0 moving=0 mode=0` | `voltage_raw ÷ 10 = V`；离线时 `ERR STATUS id=x offline=1` |
| `STATUS_ALL` | 6 行 `SLOT slot=0 name=拇指侧向 id=1 online=0 min=1023 standby=511 max=0 valid=0 press=max` + `OK STATUS_ALL profile=… armed=0` | 槽位总表（在线时额外带 pos/speed/…） |
| `MAP <slot> <id>` | `OK MAP slot=0 id=1` | 槽位重映射（成功文本未 100% 确认） |
| `SETDIR <slot> max\|min` | 错误提示 `ERR SETDIR usage_slot_max_or_min` | 设定「按下」走向哪一端 |
| `SETID <old> <new> CONFIRM` | `OK SETID old_id=1 new_id=9`；`ERR SETID new_id_occupied`；`ERR SETID write_or_verify_failed` | 改舵机 ID（写入 EEPROM） |
| `CAL STATUS` | 6 行 `CAL slot=0 name=… id=1 min=1023 standby=511 max=0 valid=0 press=max` + `OK CAL count=0 complete=0` | 查看校准表 |
| `CAL CLEAR` | `OK CAL CLEAR torque=off` | 清空校准 |
| `CAL CAPTURE <slot> <MIN> <STANDBY> <MAX>` | 失败时 `ERR CAL CAPTURE servo_read_failed` | 手动写校准值（会先读舵机验证） |
| `CAL AUTO START` | `OK CAL AUTO START` / `ERR CAL AUTO feedback_missing_slot=0_id=1 fix_ids_or_wiring_first` | 启动自动采样，**要求 6 个槽位都能读到反馈** |
| `CAL AUTO STATUS` | 6 行 `CAL_AUTO slot=0 samples=0 min=0 max=0 last=0` + `OK CAL AUTO STATUS active=0` | 采样进度（`last`=最新位置） |
| `CAL AUTO FINISH` / `CANCEL` | `OK CAL AUTO FINISH torque=off` / `OK CAL AUTO CANCEL torque=off` | 结束/取消采样 |
| `CAL SAVE` | 条件不足时 `ERR CAL incomplete_slot=0` | 保存校准（成功文本未确认） |
| `TORQUE <slot\|id> <0\|1>` | `OK TORQUE target=0 enabled=1`；`ERR TORQUE usage_slot_or_id_0_or_1` | 扭矩开关；`target=0` 表示全部 |
| `ARM` | 未校准时 `ERR ARM calibration_incomplete` | 使能动作 |
| `DISARM` | 无回复（已执行） | 失能 |
| `SAFE` | `OK SAFE torque=off armed=0` | 急停：关全部扭矩 |
| `STANDBY CONFIRM` | 缺 CONFIRM 时 `ERR STANDBY requires_CONFIRM` | 待机 |
| `PRESS <slot>` / `RELEASE <slot>` | 未 ARM 时 `ERR PRESS motion_not_armed` | 按下 / 松开某手指 |
| `MOVE <id> <pos> <speed> <acc> ARM` | 参数少时 `ERR MOVE usage_id_position_speed_acceleration_ARM` | 直接写位置（末尾必须带 `ARM`） |
| `DEMO` | 未就绪时 `ERR DEMO arm_and_calibrate_first` | 播放内置曲目 |
| `ENROLL START\|STATUS\|STOP\|RESET` | `OK ENROLL START active=1 next=1 temp=10 phase=WAIT_EMPTY requirement=first_1_to_10_then_add_id1_as_2_to_6_then_10_to_1` | 一套舵机注册流程（语义未完全摸清；用完记得 `ENROLL STOP`） |
| `AUTO` | `AUTO_BEGIN ids=1-6 attempts=3` / `AUTO_ID id=1 pings=0 identity=-1 type=none` / `AUTO_PROFILE name=STS3032 found=0 ids=none missing=1,2,3,4,5,6 unstable=none` / `AUTO_RESULT profile=AMBIGUOUS_OR_NONE found=0 ready=0 action=check_power_wiring_unique_ids_or_protocol` / `OK AUTO …` | 固件自带自检，`action=` 字段可直接读到诊断建议 |

### 2.2 协议层实战经验（非常重要）

- **改号必须一次只接一个舵机**：出厂全是 ID 1，若 6 个同时挂上，`SETID` 会同时命中多个 → 全部变成同一个 ID。
- **`SETID` 报 `write_or_verify_failed` 不代表失败**：常见情况是写入成功但回读/复核赶上了舵机重启的空窗。**判据应为「稍等后 `PING <new_id>` 是否通」**。曾因直接判失败中断整个流程。
- **改号成功后要 poll 几秒**：舵机应用新 ID 需要短暂时间，立即 ping 可能失败。
- **串口会因 USB 重新枚举而失效**，Python 侧报 `ClearCommError failed (PermissionError 13)` 或 `FileNotFoundError(2)`：前者=端口句柄失效，后者=设备消失。健壮的客户端应**捕获 `serial.SerialException` → 关闭端口 → 循环重开**。
- 逐 ID 探测时不要发广播（`PING 254`）：某些 SDK/固件在此路径会返回空包导致崩溃。
- 上位机遍历 10 个 ID ≈ 6 秒（每 ID 0.61s）；自动刷新状态建议 2~3 秒一次，避免刷爆。

## 6. 建议的后续路线

1. **恢复连接**：插好 USB-C（+ 5V/5A DC 给舵机），确认 PC 端出现 CP210x 的 COM 口。
2. **完成编号**：用 `assign_ids.py` 或网页「编号向导」，一次一个舵机把 ID 编成 1~6（顺序：拇指侧压→拇指下压→食指→中指→无名指→小指）。改号后复核 `PING`，拔下贴标签。
3. **整体自检**：6 个接回总线 → 逐个 `PING 1..6` 应全部在线；`STATUS_ALL` 应显示 `online=1`。
4. **角色确认**：`TORQUE <id> 1` 后 `MOVE <id> <pos> … ARM` 逐个驱动，确认哪个 ID 对应哪根手指、按下往哪边走；必要时 `MAP` 重映射槽位、`SETDIR` 修方向。
5. **校准**：`CAL CLEAR` → `CAL AUTO START` → 15~20 秒内反复做「拇指直按 / 拇指侧压 / 四指伸直↔握拳」→ `CAL AUTO FINISH` → `CAL SAVE`。
6. **动作验证**：`ARM` → `PRESS <slot>` / `RELEASE <slot>` 单指测试 → `DEMO` 试播内置曲目。
7. **待实现（原始需求里还有）**：
   - **按行程 80%、0~6 Hz 正弦往复驱动**：当前固件没有「频率驱动」命令。两条路——(a) 由上位机每 20~50ms 发 `MOVE` 逼近（需实测 115200 吞吐与固件 ~610ms 延迟是否可接受，很可能不够快）；(b) 改固件新增命令（源码不在本机，需要重写/重刷固件）。
   - **网页端增加「正弦/频率驱动 + 歌曲演奏」面板**（`web_piano_glove.html` 已预留结构，照着 PIANO_GLOVE 协议扩展即可）。
   - 8 只手指 vs 6 舵机的**指法映射表**（早期会话里做过《两只老虎》的映射与指法时序图，思路可直接复用：音符→(槽位, 深度比例) 动作组）。
8. **可选方向**：若嫌 PIANO_GLOVE 固件限制多，可刷微雪官方 ST 系列固件并打开 `SERIAL_FORWARDING`（串口透传），届时 `glove_calibration.py` / `web_debug.html` 这两套原始 SCS 协议工具可直接复活使用。
