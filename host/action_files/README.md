# 候选动作文件：明确指法与时值

此格式与样本仅供确认，**尚未获得甲方认可，也未部署到现有演奏页**。解析器不连接串口、不启动定时器、不产生硬件运动，不自动分配指法。JSON 文件不包含音高：它表达明确手指与时间，不承诺指定音符或跨键移动。

字段为 `version: 1`、非空 `name` 和 `events`。每个事件只包含：

| 字段 | 含义 |
|---|---|
| `t_ms` | 相对动作文件起点的计划按下时间，非负有限毫秒数 |
| `finger` | 1 拇指、2 食指、3 中指、4 无名指、5 小指，必须明确填写 |
| `duration_ms` | 从计划按下到计划松开的间隔，正有限毫秒数；不代表实机完成行程时间 |

固定候选映射为 `1→slot0、2→slot2、3→slot3、4→slot4、5→slot5`。`slot1` 为拇指侧摆，不参加事件演奏。现有网页允许对调拇指两轴，因此集成时必须核对当前角色：只有 `slot0=press、slot1=latch` 与固定映射一致时才允许进入后续人工执行流程，不能静默改映射。

解析拒绝非有限数值、负起点、非正时长、越界指法、同指重叠、缺失字段及额外字段。不同手指可同时出现。同指相接事件在数据上允许，但会提示松开间隔不足 500 ms；不把数据格式通过当作运动安全。总时长（最后结束时间）上限 300 秒、事件上限 2000；超过 30 秒提示拆短片。

`sparse-five-fingers.candidate.json` 长 **12.85 秒**，每次只含一个手指事件，按下间隔 1.4 秒、每次计划持续 250 ms。它是低密度样本，**并非已完成穿戴安全验证或 2 Hz 证明**。实际幅度、限流、使能与停止必须沿用已验证的实机校准和现有控制流程。

只解析测试：`node --test parse-action-file.test.mjs`。

建议集成点：现有 `web_piano_glove.html` 的 `play` 页新增独立“明确指法 JSON”入口，调用 `parseActionFile()` 并先展示文件名、手指、时间、总时长与警告。不要送入现有 `buildPlan(notes, mode, speed)`，该函数会分配 MIDI 指法。后续若双方确认格式，再由独立适配器转换到现有调度事件，并沿用既有校准、启停流程；文件加载与解析本身不得使能、压指或执行动作。
