# samples · 演奏测试样本

十首分级钢琴曲，给调试台第 5 页（演奏）试手感和压速度用的。

## 这些 MIDI 里**没有指法**

文件里只有四类事件：**曲名 / 速度 / 拍号 / 音符**。一个字节关于「哪个音用哪根手指」的信息都没有 ——
连轨道名都只有一句曲名，没有 Text、没有歌词（指法在 MIDI 里最常藏在这两处）。

哪根手指按哪个音，是导入时由上位机的分配算法（`web_piano_glove.html` 的 `buildPlan()`）
**现场算出来的**。所以同一首曲子换一种分配方式（轮流 / 音高对应）就是另一套指法，文件本身不用改。

> 这不是"省事"，是刻意设计：指法要和**具体的手套**绑定（哪个槽位是哪根手指、校准到哪、方向如何），
> 而这些信息不在曲子里。把指法写进 MIDI，换一副手套就得重做一遍样本。

自检是机器做的，不靠人看：`make_samples.py` 每生成一个文件就解析一遍，
出现 `Text(0x01)` / 歌词(0x05) 之类的 meta 直接报错退出。e2e 里也有一条对应的断言。

**想要指法？看 [FINGERING.md](FINGERING.md)** —— 那是跑**页面里同一份** `buildPlan()` 导出的，不是人写的谱。

## 一条实测结论：光靠「音符密」压不垮手套

原本 L5 准备的是一首极快的单音跑动（十六分音符半音阶），**结果零丢音**。
翻 `buildPlan()` 才发现原因：触键时长被夹在 **55~200ms**，5 根手指轮转绰绰有余 ——
单声部旋律不管多快，同一时刻也只占一根手指。

真正决定成败的是**同一时刻要几根手指**。所以 L5 换成了《革命练习曲》：
左手十六分琶音 + 右手每拍一记柱式和弦，拍点上同时响 5 个音，6 根手指用掉 5 根。
可比的指标是**峰值命令速率**：L1 是 4 条/秒，L5 是 44 条/秒。

（`catalog.json` 里有这些曲子的结构化元数据，供文档和校验脚本用。）

## 重新生成

```bash
python host/tests/make_samples.py            # 生成 10 首 .mid + catalog.json，并同步进调试台
python host/tests/make_samples.py --list     # 只看清单，不写文件
node   host/tests/fingering_report.js        # 重新导出 FINGERING.md 指法表
```

`make_samples.py` 跑完会**自动把曲库内嵌进 `web_piano_glove.html`** ——
`.mid` 文件是唯一真相源，网页里那份 base64 由它派生，两边不会各说各话（e2e 有断言逐字节比对）。

网页用内嵌而不是 `fetch`，是因为调试台要能双击直接打开（`file://`），
而 `file://` 下 fetch 本地文件会被浏览器拦掉，曲库会整个失效。

## 在调试台里怎么用

1. 走完第 3 步（校准）和第 4 步（试动作），第 5 页才会解锁
2. 第 5 页顶部「曲库」下拉按 L1~L5 分好组，选中即载入
3. 载入后不用按播放，卷帘图就画出了总览 —— 可以先看这首曲子手套要做什么
4. 点「开始演奏」才会出声（浏览器的自动播放策略），再点播放键左边的「播放声音」可以静音

也可以直接从文件管理器把 `.mid` 拖到虚线框里，用自己找的曲子。
